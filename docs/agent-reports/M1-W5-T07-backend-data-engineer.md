## Transport request (blocker for the lead / ShiftRoom owner, `apps/server/src/net/**` was off limits)
`net/http-routes.ts` JSON-parses the body and caps it at `MAX_HTTP_BODY_BYTES = 16 KB`, and `HttpResponse` can only be JSON. An MCCK package (up to 1 MB) cannot pass through it, so on the live server the upload answers 400 and the download cannot be sent. The handlers are written against a seam and tested through it:
- request: `request.rawBody?: Uint8Array` (route-specific limit 1 MB, only for `checkpointUpload`; `content-type: application/octet-stream`, no JSON parse);
- response: `HttpResponse & { binary?: Uint8Array }` written as the body with the given headers (`content-type`, `x-save-pages`);
- metadata travels in header `x-mc-checkpoint-meta` = base64url JSON of `SoloCheckpointBeginRequest` (<= 4096 chars). This replaces the multipart in the contract text; contracts-architect should confirm or choose another carrier.
- CORS must allow request header `x-mc-checkpoint-meta` and expose `x-save-pages`, `retry-after`.
`head` is plain JSON and works today.

## Trust model
The server verifies the container, never the content.
- Verified: Bearer JWT; caller is an active Holder of a non-deleted `shift_type = solo` Contract (strangers get 404, non-Holder 422 `not_holder`); body <= 1 MB (413 above); metadata zod-strict; package magic/version, every length bounds-checked, trailer CRC32 equals `packageCrc32`; header gunzip bounded to 1 MB and each chunk inflate bounded to 256 KB (decompression bombs give `size_limit`), envelope magic, section table adds up, envelope CRC32, chunk `rawSize` and CRC32 recomputed; chunk ids 0-640 and unique; envelope generation/parent/origin(solo)/format/bakeHash equal the metadata and package; `gridM`/`plotCount` equal the Contract's; `saveFormatVersion` newer than the server's gives 409 `SAVE_VERSION_UNSUPPORTED`; `generation > parentGeneration` and above the server's newest (also for overwrite).
- Concurrency/CAS in one transaction under `SELECT ... FOR UPDATE` on the Contract: live lease (`lease_expires_at > db now`) gives 409 `CONTRACT_BUSY`; accepted only if the server's newest `save_seq` equals `baseGeneration` (else 409 `SAVE_CONFLICT` with the server summary, nothing written) unless `overwrite`; older slot overwritten with CAS on that slot's `save_seq` (zero rows rolls back); chunks go to their older version; >= 20 s gap by the database clock (429 + `retry-after`); <= 60 uploads/h per player (in memory); per-Contract `stored_bytes` hard cap 8 MB (rolls back, 422 `size_limit`). Same device re-sending the stored generation is an idempotent 200 (lost acknowledgement).
- NOT trusted / not checked: all section bodies and dust payload content (wallet, plots, unlocks, Shine). A player may edit their own solo save; that is accepted by design (ADR-0031). `shinePolished` is clamped to `plot_count`, wallet to [0, 1e12], playtime stored as claimed; these mirrors only feed that player's own lists.
- Shared surfaces: profile credit (tenure, commendations) = min(claimed, per-hour cap x accepted playtime delta); caps are PLACEHOLDERS (600 tenure/h, 6 commendations/h) until game-data supplies them. Playtime delta is clamped to wall-clock since the last accepted upload x 1.05 + 120 s. An implausible upload (playtime or tick delta above bound, shine above plot count, non-finite wallet) is ACCEPTED, flagged `solo_implausible`, audited, and credits nothing. Achievement ids are ignored (no catalog yet).
- Errors are uniform codes; a rejection never echoes content. DB-unreachable gives 503 via the existing `safe` wrapper.

## Decisions to confirm
1. Dust chunks table: migration 0003 creates `contract_dust_chunks` (data-model 3.7b; it did not exist). W5-T01 (room checkpoints) should reuse it and `save-rules.ts` (`pickOlderSlot`, `pickOlderVersion`, signed-CRC helpers).
2. Download pages are 0-based (`page` default 0, contract schema); page 0 carries the header, later pages `headerLen 0`. The checkpoint-package comment says "page 1"; the REST schema wins.
3. Download re-verifies the slot and every chosen chunk (inflate + CRC) under the single-concurrency queue and falls back per the 3.7b load rule (ignores chunk rows newer than the chosen header). A fully corrupt save answers 500 `INTERNAL`.
4. `abuse_events` table does not exist: flags go to the `audit` hook (logged), as in W4-T05. Persisting them needs a table migration (W5-T01 or a later card).
5. CRC32 columns store the signed int32; repository converts both ways (round-trip tested including 0xdeadbeef).
6. Rate limiters are per process, in memory (reset on restart); the 20 s gap and CAS live in the database.
